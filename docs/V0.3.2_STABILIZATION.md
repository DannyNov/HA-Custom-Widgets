# Dashboard v0.3.2 stabilization

## Runtime architecture

Glance callbacks are local-only. Navigation updates a per-widget StateFlow and a small UI preference. Control callbacks persist an optimistic operation and enqueue unique WorkManager work keyed by widget and entity. Refresh callbacks enqueue unique per-widget work.

Dashboard state is split into structure, per-entity versioned states, operation metadata, and small UI/config preferences. Home Assistant last_updated timestamps plus active operation IDs prevent older responses from replacing newer accepted state.

Home Assistant state_changed events are consumed through a best-effort WebSocket while the application process is alive. Every connection/reconnection performs a REST reconciliation. Periodic WorkManager state refresh is the process-death, Doze, and vendor battery-management fallback. No foreground service or permanent notification is enabled automatically.

## Diagnostics

Logcat tags:

- HAWidgetDashboard
- HAWidgetDashboardAction
- HAWidgetDashboardUpdate
- HAWidgetActionWorker
- HAWidgetRefreshWorker
- HAWidgetEvents

Logs contain widget/entity/operation identifiers and stage timings. They never contain the Home Assistant URL or token.

## Honor Launcher manual matrix

1. Switch between spaces ten times, then repeat immediately after launch, during refresh, and during a control action.
2. Test ON to OFF, OFF to ON, a repeated tap, two devices in sequence, and two controls from one device.
3. Change a device in Home Assistant, another Android widget, and physically or through an automation; record Dashboard latency.
4. Return to the launcher, kill the app process, reboot, disable the network, then restore it.
5. Scroll far down and repeat action, refresh, and external state-change tests; record whether Honor preserves the collection position.

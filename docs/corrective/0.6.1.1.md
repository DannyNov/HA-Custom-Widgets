## Cause and correction

Reconciliation treated a current storage schema as a current HA catalog. It fetched only already-known entity IDs; it could neither discover new cards nor update names/area membership. Configuration save fetched a fresh catalog and rebuilt the structure, explaining both workarounds.

The structure now records its last successful catalog refresh separately from state freshness. Existing v0.6.1 snapshots lack that timestamp and refresh on the next reconciliation without resetting configuration or changing the storage schema. Catalogs expire after 15 minutes. Existing WorkManager sync (15-minute interval, subject to Android scheduling) and foreground/screen-on/widget navigation reconciliation provide automatic recovery independently of HA registry events. Manual refresh bypasses catalog age. State events do not fetch catalogs or extend their freshness. No new event subscription, polling service or reconnect loop was added.

The process-wide reconciliation mutex serializes fetches. One catalog serves all due Dashboard instances and provides state data for remaining widgets. State merging retains existing HA timestamp arbitration against concurrent WebSocket updates. Catalog failure leaves the previous snapshot and freshness intact for retry. Subscription membership updates use the existing in-place subscription replacement path.

Removed cards/scenarios leave the active structure and subscription set. User preferences for missing IDs remain available for reappearance: visibility, order, favorites, timers, grouping and scenario settings. Missing spaces no longer erase selected spaces/order; an unavailable selected tab is rendered as a fallback without overwriting the stored choice. A missing configured timer is retained in preferences but is not repeatedly polled as an active dependency until the catalog contains it again.

## Physical Honor checks

Install the CI-signed APK over v0.6.1 without uninstalling. Do not use a locally debug-signed APK for this upgrade.

1. Configure a Dashboard, record card order, hidden devices/entities, favorites, grouping, selected tab and timer presets. Close settings.
2. Add a supported device or standalone entity in a selected HA space. Without opening widget settings or tapping Refresh, allow an automatic sync (normally the next 15-minute background opportunity; Android may defer it). If overdue, turn the screen off/on or return to the app. Verify the new card appears and is visible.
3. Rename an existing HA device, entity, area and floor. Wait for automatic sync without opening settings; verify names and stable IDs, configured order, visibility and timers.
4. Remove an entity/device; move another between selected areas/spaces. Verify old cards/membership disappear and destination membership appears. Reintroduce an object with the same HA ID and verify retained preferences.
5. Add/rename/remove automation, script and scene entries; verify the Scenarios tab while preserving runnable/hidden choices.
6. Exercise normal state changes: updates remain responsive. Test manual Refresh separately for immediate catalog reload.
7. Verify HA timer.finished automation still owns auto-off, including with the phone offline. No client timer-expiry execution was changed.

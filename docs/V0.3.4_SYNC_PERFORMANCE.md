# v0.3.4 external synchronization and Dashboard performance

## WebSocket lifecycle

The event transport is explicitly best effort while the Android application process is alive.
It uses the following state machine:

`IDLE -> CONNECTING -> AUTHENTICATING -> SUBSCRIBING -> SUBSCRIBED`

Any bounded-stage timeout, close, failure, rejected subscription, or stale watchdog result enters
`BACKOFF`. Backoff is `1, 2, 4, 8, 16, 30, 30...` seconds. Every physical socket has a monotonic
generation and a random connection ID. Callbacks are accepted only for the current socket identity.

Deadlines:

- physical WebSocket connect: 12 seconds;
- `auth_required`: 8 seconds;
- `auth_ok`: 10 seconds;
- `subscribe_events` result: 10 seconds.

OkHttp sends protocol pings every 20 seconds. After subscription the coordinator also sends a Home
Assistant `ping` command every 30 seconds. If no message/pong arrives for 75 seconds, the generation
is closed and reconnected.

Every successful `SUBSCRIBED` transition requests a targeted REST reconciliation. Reconciliation is
single-flight: overlapping process-start, reconnect, Activity, AppWidget, action, refresh and worker
requests share a mutex and a later request is skipped when the preceding snapshot completed after it
was requested. A persisted per-widget snapshot is considered fresh for 120 seconds on ordinary wake
paths. Forced reconnect/manual/periodic snapshots bypass the age threshold but still coalesce when
they overlap.

No foreground service or persistent notification is introduced. If Android/Honor kills the process,
EVENT delivery is impossible until a natural wake starts the process. Process start, AppWidget
`onUpdate`, Activity resume, configuration open/save, Dashboard actions, connectivity availability,
manual refresh and periodic WorkManager all restart the coordinator and reconcile when needed.

## Navigation hot path

STRUCTURE JSON is parsed once per process/configuration revision and cached as an immutable runtime
snapshot. It includes entity IDs, area/card and space/card indices. An entity-to-widget index is kept
for EVENT mapping and invalidated with structure changes.

Changing the selected tab or collapsed section now:

1. writes only the UI preference;
2. publishes one copied in-memory Dashboard state;
3. commits one monotonic render revision without calling `loadState()`;
4. requests one coordinated render.

It no longer emits an intermediate composition followed by a full structure parse and second
composition.

Logcat contains `NAV_TAP`, `NAV_STATE_COMMIT`, `STATE_LOAD_START/END`, `COMPOSITION_START/END`, and
`RENDER_REQUEST/START/SUCCESS`. State-load diagnostics include total cards, selected-space cards,
entity count and structure byte size. Physical small/medium/large timings must be collected on the
Honor launcher because JVM/CI cannot measure launcher RemoteViews application time.

## Stable ordering and long-press drag

All arrow reorder controls in Dashboard settings are replaced by one reusable stable-ID
`ReorderableList` Compose pattern. Normal vertical movement scrolls. Reordering begins only after a
long press, lifts the selected item, updates neighboring positions, and auto-scrolls near either edge.

Visible selection and complete space order are stored separately. v0.3.3 configuration migrates by
using its visible stable-ID list as the initial order. Catalog merges retain surviving user order,
remove deleted IDs, and append new IDs. Titles are metadata only, so HA renames do not alter order.

## Honor verification matrix

1. Keep the application process alive and perform 50 external changes from HA UI, another widget,
   and a physical device. Record EVENT-to-RENDER latency and success count.
2. Disconnect/reconnect Wi-Fi, restart HA and switch networks. Verify `WS_FAILURE/CLOSE -> BACKOFF ->
   WS_SUBSCRIBE_OK -> RECONCILE_SUCCESS` without manual refresh.
3. Kill the process, change an entity, then trigger the first natural wake. Record time until REST
   truth is rendered; do not classify the missing dead-process EVENT as a WebSocket failure.
4. For spaces near 5, 20 and 50 cards, record `NAV_TAP`, `NAV_STATE_COMMIT`, `RENDER_START` and
   `RENDER_SUCCESS`. Confirm `publications=1`.
5. Reorder `Дача, Квартира Омская, Офис` into `Офис, Дача, Квартира Омская`; Save, reopen settings,
   restart the process and check Dashboard navigation order.
6. Verify normal scroll, long press, upward/downward drag, edge auto-scroll, cancel and drop.
7. Repeat v0.3.3 ON/OFF, failure, reversal, deadline, repeated-tap and simultaneous-entity tests.

# HA Dashboard v0.3 — архитектура и ограничения

## Источник пространственной структуры

Dashboard не создаёт собственные пространства. Он читает через официальный WebSocket API:

- `config/floor_registry/list`;
- `config/area_registry/list`;
- `config/device_registry/list`;
- `config/entity_registry/list`.

Home Assistant определяет Area как помещение/пространство, а Floor как группу Areas. Поэтому:

- если Floors не настроены, вкладками становятся Areas;
- если Floors настроены, вкладками становятся Floors, а их Areas — секциями помещений;
- Areas без Floor остаются самостоятельными вкладками;
- устройства и сущности без Area доступны во вкладке «Без пространства».

Area, заданная непосредственно у Entity, имеет приоритет над Area устройства — это соответствует
модели Home Assistant. Переименование и изменение структуры попадает в Dashboard при ручной или
фоновой синхронизации.

## UI App Widget

Виджет построен на стабильном Jetpack Glance и использует один `LazyColumn`. Шапка и переключатель
вкладок находятся вне коллекции, поэтому остаются видимыми при вертикальной прокрутке.

Стабильный Glance AppWidget не предоставляет горизонтальный `LazyRow` для вкладок. Поэтому вместо
ненадёжной имитации горизонтального скролла используются кнопка `★`, стрелки назад/вперёд и название
текущей вкладки. Long-press и double-tap не перехватываются: long-press остаётся launcher, а double-tap
не реализован из-за отсутствия надёжного AppWidget gesture API.

## Данные и обновления

REST `/api/states` и `/api/states/{entity_id}` остаются источником состояний. Registry API работает
через короткий WebSocket-сеанс во время синхронизации. Постоянное WebSocket-соединение не держится в
фоне: Android не гарантирует жизнь процесса AppWidget, а WorkManager/ручное обновление предсказуемее.

После действия обновляется только целевая сущность. Полная registry/state синхронизация выполняется
вручную либо периодическим WorkManager. Конфигурация и последний подтверждённый снимок хранятся
отдельно для каждого widget ID.

## Действия

Поддерживаются service calls:

- `light/switch/input_boolean.toggle`;
- `button.press`;
- `script/scene.turn_on`;
- `timer.start` и `timer.pause`.

До завершения команды карточка помечается состоянием отправки. Повторный tap того же устройства
блокируется на короткое время. После service call приложение запрашивает подтверждённое состояние;
при ошибке снимает блокировку и показывает ошибку обновления.

## Ограничения, требующие проверки на устройстве

- фактическая высота, плавность прокрутки и сохранение позиции зависят от launcher;
- конкретный launcher определяет минимальный/максимальный размер и форму скругления;
- Glance не гарантирует частичное обновление одной строки коллекции, поэтому после действия
  пересобирается RemoteViews экземпляра, хотя по сети запрашивается только одна сущность;
- сложные controls (`cover`, `climate`, `fan`, `media_player`, `lock`) оставлены для следующих версий;
- drag-and-drop внутри Compose-экрана не добавлен: для предсказуемой первой версии используются
  явные кнопки вверх/вниз, сохраняющие тот же порядок данных.
